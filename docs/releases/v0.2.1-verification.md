## 2. P0-2：核心缺陷的定位与修复（历史性根因）

### 2.1 现象（原 0.2.1 实现）

隐藏任务栏后：
- 工作区本应被接管为 `(0,32)-(1920,1080)`（顶栏 32px，底部到屏幕底）；
- 实测工作区**周期性**回落到 `(0,32)-(1920,1032)`（底部 48px 任务栏条带被重新预留），每次约 0.5 s；
- Windows 在条带回落瞬间会把所有最大化窗口压回 1032–1034，**之后不会自行长回**。

100 ms 采样（20 s）原始记录：

```
t=0ms      wa=(0,32)-(1920,1080) tb_visible=False alpha=0
t=3647ms   wa=(0,32)-(1920,1032) tb_visible=False alpha=0
t=3807ms   wa=(0,32)-(1920,1032) tb_visible=True  alpha=0   <-- 桥接 SW_SHOW
t=3915ms   wa=(0,32)-(1920,1032) tb_visible=False alpha=0
t=4132ms   wa=(0,32)-(1920,1080) tb_visible=False alpha=0
t=13685ms  wa=(0,32)-(1920,1032) tb_visible=True  alpha=0   <-- ~10 s 后再次
```

最大化窗口几何（同一时刻）：

```
zoomed=True winrect=(-8,24)-(1928,1040) visibleFrame=(0,24)-(1920,1034)
workarea=(0,32)-(1920,1080) screen=1920x1080      <-- 窗口底边 1034，永久留条带
```

### 2.2 根因

1. `ui/js/tray.js` 的托盘镜像每 **10 s** 刷新一次（`REFRESH_MS = 10000`）；
2. 刷新走 `winapi::tray::enumerate()` → `taskbar::bridged()` → `begin_hold()` → `show_taskbar()`；
3. `show_taskbar()` 对 `SW_HIDE` 的任务栏执行 `ShowWindow(SW_SHOWNOACTIVATE)`（alpha=0，肉眼不可见）；
4. 任务栏窗口一旦「显示」，Explorer 立即按**仍注册的任务栏 AppBar** 重算工作区，把底部 48px 重新预留；
5. 周期与 10 s 刷新完全吻合（见 §2.1 采样），每次托盘刷新、每次托盘点击都会触发。

即：**`SPI_SETWORKAREA` 静默接管本身生效，但任何一次任务栏窗口可见性跳变都会把它冲掉，而最大化窗口的收缩是不可逆的。**

### 2.3 修复（`src-tauri/src/winapi/taskbar.rs`，另 `winapi/tray.rs` 一行）

- 新增「隐身模式」为默认隐藏方式：任务栏窗口**保持 visible**，同时 `WS_EX_LAYERED` + alpha 0 + `WS_EX_TRANSPARENT`（鼠标穿透）。
  - 没有任何 `SW_SHOW`/`SW_HIDE` 跳变 ⇒ Explorer 不再重算工作区；
  - alpha=0 ⇒ 用户不可见；`WS_EX_TRANSPARENT` ⇒ 底部 48px 的鼠标事件穿透到下层窗口（最大化窗口底部仍可点）。
- `begin_hold()` 在隐身模式下**只调 alpha、不切可见性**，并强制 alpha=0（忽略旧的「可见兜底」255，避免任务栏闪现）。
- 新增 `clickable_guard()`：**只在真正发指针事件时**（托盘点击）临时去掉穿透约 100 ms，UIA 枚举不动穿透（否则每次刷新会在底部制造死区）。
- `restore_all()`：与桥接用 `BRIDGE_LOCK` 串行，且恢复时同时清除 `WS_EX_LAYERED` / `WS_EX_TRANSPARENT`，避免"任务栏可见但点不动"。
- 崩溃残留自愈：`apply()` 发现窗口已是 alpha=0 + 穿透且无原始 exstyle 记录时，把"去掉这两位的样式"作为恢复目标。
- `SW_HIDE` 仅作为隐身不可用（UIPI 拒绝改样式）时的兜底；watchdog 在隐身模式下每 tick 维持 alpha/穿透/可见。

### 2.4 修复后验证（交付构建）

任务栏状态：

```
Shell_TrayWnd: visible=True layered=True transparent=True alpha=0 exstyle=0x800A8 rect=(0,1032,1920,1080)
workarea=(0,32)-(1920,1080)
```

100 ms 采样：
- 20 s：**0 次**工作区跳变
- 25 s：**0 次**工作区跳变（唯一变化是穿透标志在托盘点击链路 ≈100 ms 的临时关闭/恢复，工作区不动）

最大化保持测试（新建 Notepad → `SW_MAXIMIZE`，每 5 s 采样，40 s，横跨 4 个托盘刷新周期）：

```
t+1s   zoomed=True winrect=(-8,24)-(1928,1088) visibleFrame=(0,24)-(1920,1080) workarea=(0,32)-(1920,1080)
...
t+40s  zoomed=True winrect=(-8,24)-(1928,1088) visibleFrame=(0,24)-(1920,1080) workarea=(0,32)-(1920,1080)
RESULT: PASS (visibleFrame bottom 1080 == screen height 1080)
```

> 注：验收口径为 `visibleFrame`（DWM 可见边框）底边 == 屏高；`GetWindowRect` 因最大化窗口的不可见缩放边框会比屏高大 8px，属正常。

## 3. P0-4：强杀与恢复

| 步骤 | 观察 |
| --- | --- |
| 任务栏处于隐身态时 `taskkill /F` | 任务栏保持 `visible=True alpha=0 transparent=True`（用户仍看不到），`taskbar-hidden.lock` 存在；工作区被 Explorer 自动还原为 `(0,0)-(1920,1032)`（进程死亡 → 其顶栏 AppBar 注销） |
| 重新启动 | `recover_stale_lock()` 先恢复 → 再次进入隐身模式；状态回到 `alpha=0 + 穿透 + workarea (0,32)-(1920,1080)`，marker 重写 ✅ |

结论：**强杀不会让用户永久失去任务栏**；重启即自愈。崩溃瞬间桌面会短暂呈现"任务栏不可见但底部 48px 空白"，下次启动自动纠正。

收尾（等价 `restore_all` 的提权清理）后：

```
taskbar: visible=True layered=False transparent=False exstyle=0x88
workarea=(0,0)-(1920,1032)   marker=absent   进程=未运行
```

即任务栏外观、可点击性、工作区全部还原。

> UIPI 说明：非提升进程**无法**修改 explorer 的任务栏窗口样式（实测 `SetWindowLongPtr` 无效），
> 这也解释了 `requireAdministrator` 清单的必要性；恢复动作必须由应用自身（提升）或提权脚本完成。

## 4. P0-3：托盘图标点击

后端链路有日志证据（`%APPDATA%\com.easydash.app\tray-click.log`）：

```
ts_ms=1793025489606 idx=3 btn=right at=(1441,1056) mode=invisible-mouse popup=0x5d13d4 rect=(1404,40,352,68) found_ms=564 held_ms=60049 err=-
ts_ms=1793027370769 idx=4 btn=right at=(1537,1056) mode=invisible-mouse popup=- rect=- found_ms=1549 held_ms=1549 err=-
```

- `mode=invisible-mouse`：点击期间任务栏以「显示但 alpha=0」桥接，真实指针事件命中；
- `popup=0x5d13d4 rect=(1404,40,352,68)`：右键菜单被找到并**重定位到顶栏图标下方**，`held_ms=60049` 表示保持到 60 s 上限（菜单一直开着）；
- `err=-`：点击本身无错误。

限制说明：本会话第二轮用程序化注入（`SetCursorPos` + `mouse_event`，含绝对坐标与长按变体）点击顶栏 WebView 时，点击会**穿透到下层窗口**（把下方 Notepad 的右键菜单打开了），因此未能重复"左键面板 / 右键菜单"的人工确认。同一注入在 Explorer / 对话框 / Notepad 上工作正常，故判断为注入路径与顶栏 WebView（`WS_EX_NOACTIVATE` + 透明 WebView2）的交互问题，而非应用逻辑问题；托盘点击的后端链路本身有上述日志证据。

## 5. 待人工确认（约 1 分钟）

1. 启动 easy-dash（安装包或 `easy-dash.exe`，UAC 允许）。
2. **托盘左键**：左键点顶栏最右侧的 easy-dash 图标（黑色圆角方块 + 白色横条 + 三个点）→ 应出现面板；**右键** → 应出现「打开 / 重载配置 / 退出 easy-dash」菜单。
3. **正常退出**：右键该图标 →「退出 easy-dash」→ 任务栏应立即恢复（可见、可点），窗口不再被压条带。
4. **关闭开关**：顶栏设置（齿轮）→ 管理面板 → 关闭「隐藏系统任务栏」→ 任务栏恢复；再打开 → 重新隐藏。
5. **重载配置**：托盘菜单 →「重载配置」→ 任务栏应短暂恢复后再隐藏，且工作区仍为 `(0,32)-(1920,1080)`。
6. **主题**：控制中心「外观」只应有浅色/深色两段；切换时 5 个窗口同步；开「同时控制系统主题」时
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` 应被写入。
